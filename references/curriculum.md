# 默认 AI 产品技术知识地图

这是一条面向 AI 产品经理、产品运营和非算法岗位的默认路线。它回答“先学什么、后学什么”，不限制用户按工作问题跳转。

## 使用方法

- 新课程：先用一个工作情境诊断，不要逐项询问学习者是否会。
- 继续课程：以学习档案为准，选择最早的未完成依赖或用户指定主题。
- 用户已有工程基础：允许跳过已能迁移应用的 Block。
- 新主题不在地图中：放入最接近的阶段；若它服务于用户目标，可以新增个性化 Block。
- 不因课程顺序阻止必要追问，但要区分“当前需要理解”和“后续再系统学习”。

教学类型：

- 系统：案例拆解、信息流、故障定位。
- 机制：直接讲解、概念对比、机制图、少量检索题。
- 实验：观察真实输入、中间结果和输出。
- 工程：数字计算、性能实验、故障排查、方案比较。
- 判断：综合案例、取舍、反例挑战和方案评审。

## 1 看懂 AI 产品

| Building Block | 类型 | 本阶段最低产出 |
|---|---|---|
| AI 产品基本结构 | 系统 | 解释模型与完整产品的关系 |
| AI 产品的六个构建块 | 系统 | 区分界面、流程、数据、模型、工具、评测 |
| 生成式 AI 与传统软件 | 判断 | 判断任务应交给模型、规则代码还是人工 |
| 一次问答的完整链路 | 系统 | 画出信息流并沿链路定位错误 |

阶段完成标准：面对一个陌生 AI 产品，能拆出主要组成、数据流、确定性与概率性环节，并说明基本风险控制。

## 2 看懂模型

| Building Block | 类型 | 本阶段最低产出 |
|---|---|---|
| Token | 机制 | 解释切分、上下文占用和计费关系 |
| 上下文窗口 | 机制 | 区分上下文、历史、长期记忆和知识库 |
| Base、Instruct 与 Chat 模型 | 机制 | 根据任务选择合适模型形态 |
| 开放权重与闭源 API | 判断 | 比较部署、成本、控制、合规和许可证 |
| 模型参数与 MoE | 机制 | 区分总参数、激活参数和实际部署代价 |
| 多模态模型 | 系统 | 区分多模态模型与多组件产品并分层评测 |
| Temperature、Top-p 等推理参数 | 机制 | 解释采样参数能和不能改变什么 |
| 幻觉与模型能力边界 | 判断 | 区分数据、检索、工具、推理和生成错误 |

阶段完成标准：能阅读常见模型规格，理解模型生成边界，并把产品错误准确归因到完整链路。

## 3 看懂训练

| Building Block | 类型 | 本阶段最低产出 |
|---|---|---|
| 预训练 | 机制 | 解释预测下一个 Token 与通用能力的关系 |
| SFT（监督微调） | 机制 | 解释指令－理想回答数据如何改变模型行为 |
| RLHF、DPO 与 RL | 机制 | 区分偏好、安全和强化学习的主要目标 |
| 训练数据与数据质量 | 判断 | 识别覆盖、标注、偏差、污染和许可风险 |
| 微调与 LoRA | 判断 | 判断 Prompt、RAG、工具或微调哪个更合适 |
| 蒸馏、量化与模型压缩 | 工程 | 比较质量、资源、速度和部署取舍 |

阶段完成标准：面对一个能力改进需求，能说清训练阶段、数据要求、替代方案和评测方式。

## 4 看懂知识与工具

| Building Block | 类型 | 本阶段最低产出 |
|---|---|---|
| Prompt 的角色与结构 | 实验 | 观察角色、上下文、约束和示例如何影响输出 |
| Embedding | 机制 | 解释语义向量及相似度的用途与边界 |
| 向量数据库 | 系统 | 解释向量检索、元数据过滤和普通数据库的分工 |
| RAG（检索增强生成） | 实验 | 观察切分、召回、上下文和生成的中间结果 |
| Function Calling / Tool Use | 系统 | 区分模型提议、流程校验与工具执行 |
| Agent | 系统 | 解释循环、状态、工具、停止条件和失败恢复 |
| Memory | 系统 | 区分短期上下文、长期记忆、来源和更新机制 |
| MCP | 系统 | 解释标准化工具/资源接入与具体业务授权边界 |

阶段完成标准：能画出知识或工具如何进入模型，并设计权限、校验、失败降级和可观测节点。

## 5 看懂工程与成本

| Building Block | 类型 | 本阶段最低产出 |
|---|---|---|
| API 请求与流式输出 | 实验 | 观察请求、首 Token、完整输出和错误状态 |
| 推理与模型服务 | 工程 | 解释托管 API、自建服务及关键运行组件 |
| 延迟、吞吐与并发 | 工程 | 区分三者并找到性能瓶颈 |
| Token 计费与成本结构 | 工程 | 计算单次和规模化成本 |
| 缓存 Token / Prompt Caching | 工程 | 判断缓存命中、上下文占用和节省边界 |
| 模型路由与降级 | 判断 | 设计质量、成本、超时和不可用时的策略 |
| 监控与可观测性 | 系统 | 定义链路记录、质量指标、报警和隐私边界 |

阶段完成标准：能估算一个方案的成本与性能，设计失败处理，并说明上线后如何观察真实质量。

## 6 做出产品判断

| Building Block | 类型 | 本阶段最低产出 |
|---|---|---|
| 模型选型 | 判断 | 用真实任务集比较质量、延迟、成本和约束 |
| 评测集与 Golden Set | 判断 | 构建有代表性、可维护且避免泄漏的评测集 |
| 自动评测与 LLM-as-a-Judge | 判断 | 识别评审标准、偏差、校准和人工抽检需求 |
| 人工评测 | 判断 | 设计评分标准、一致性检查和分歧处理 |
| A/B 测试 | 判断 | 定义假设、指标、分流和停止条件 |
| Prompt Injection 与越狱 | 判断 | 区分不可信输入、权限控制和输出防护 |
| 数据隐私、版权与内容安全 | 判断 | 识别数据流、用途、留存、授权和风险责任 |
| 效果、成本与速度的取舍 | 判断 | 给出约束明确、可验证的产品方案 |

阶段完成标准：能评审一套 AI 产品方案，指出证据不足、主要风险、验证方式和可接受的取舍。
